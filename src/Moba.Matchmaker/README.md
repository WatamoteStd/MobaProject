# Moba.Matchmaker (Console Service)

 Выделенный консольный сервис подбора игроков (Matchmaking) по уровню навыка (MMR) и времени ожидания в очереди.

---

## 1. Основные возможности
- Поддержка вариативных игровых режимов
- Динамическое расширения диапазона поиска 
- Отдельный фоновый поток для формирования матчей
- Основной поток для управление сервисом
- *Связь с сервером без задержек благодаря использованию технологии gRPC* **(feature)***

---

## 2. Архитектура и ключевые компоненты

###### Язык разработки: C# | Фреймворк: Net 10.0

- **Pool Player:** Сущность игрока передаваемая по всем последующим компонентам. 
    * **ID** *(long)* — уникальный идентификатор игрока.
    * **JoinedQueue** *(DateTime)* — время входа в очередь.
    * **MMR** *(int)* — рейтинг игрока.

- **Match Result:** Сформировавшаяся структура матча.
    * **Players** *(PoolPlayers[])* — Массив игроков данного матча.
    * **Mode** *(MatchProperty ..enum)* — игровой режим матча.

- **Matchmaking Pool:** Объект. Является пулом определенного игрового режима.
    * **Pool Type** *(MatchProperty ..enum)*
    * **_players** *(Dictionary<long, PoolPlayer>)* — словарь игроков этого пулла.
    * **_lock** *(ReaderWriterLockSlim)* — Обеспечивает производительную потокобезопастность.

- **Matchmaking Manager:** Создает и управляет всеми игровыми пулами. Добавляет и удаляет из них игроков.
    * **_soloPool** *(MatchmakingPool)* — пулл для игры 1 на 1.
    * **_trioPool** *(MatchmakingPool)* — пулл для игры 3 на 3.
    * **_fullPool** *(MatchmakingPool)* — пулл для игры 5 на 5.

    * Основные методы:
        * **Add Player** — в качестве аргументов принимает тип матча и *PoolPlayer*. Добавляет игрока в указанный пулл.
        * **Remove Player** — использует те же аргументы что и **"AddPlayer"**. Удаляет игрока из указанного пулла.
        * **Get Pool** — использует в качестве аргумента тип матча. Возвращает пулл.

- **Matchmaking Engine** — осуществляет подбор игроков для каждого из пуллов.
    * **Base MMR Range** *(int)* — базовый разброс ммр при поиске противников.
    * **MMR Expansion Per Secound** *(int)* — число на которое увеличивается разброс ммр в зависимосьт от времени ожидания.
    * **Max MMR Range** *(int)* — ограничитель для максимального разброса ммр. Разброс ммр не может быть выше этого числа. По умолчанию = 0 ( разброс не ограничен )
    * Основные методы:
        * **Find Match()** — в качестве аргументов принимает тип матча и spapshot *(список игроков из пулла на данный момент времени)*. В результате работы выдает структуру "Match Result" или список данных структур.
- **Matchmaking Loop** — фоновый оркестратор. Крутит бесконечный цикл в отдельном потоке, опрашивает пулы и запускает алгоритм подбора.
    * **_thread** *(Thread)* — выделенный поток для работы цикла.
    * **_manager** *(MatchmakingManager)* — ссылка на менеджер пулов.
    * **_engine** *(MatchmakingEngine)* — ссылка на математическое ядро.
    * **_isWorking** *(bool)* — флаг работы цикла.
    * Основные методы:
        * **Start()** — инициализирует и запускает фоновый поток.
        * **Stop()** — корректно останавливает цикл.
        * **ProcessQueue()** — снимает снапшоты пулов, вызывает `Engine.FindMatch()` и удаляет сматченных игроков из `Manager`.

## 3. Алгоритм работы

Процесс поиска и формирования матча происходит по следующему циклу:

1. **Поступление заявки:** Игрок через `MatchmakingManager.AddPlayer()` попадает в словарь нужного `MatchmakingPool`. Фиксируется точное время входа (`JoinedQueue = DateTime.UtcNow`).
2. **Тик опроса:** `MatchmakingLoop` с заданным интервалом запрашивает снапшот (копию списка) активных игроков пула.
3. **Расчет динамического MMR-окна:** Для каждого первого неподобранного игрока в списке высчитывается допустимый разброс по формуле:
   $$\text{Delta} = \text{BaseMmrRange} + (\text{TotalSeconds} \times \text{MmrExpansionPerSecound})$$
   *(Если задан `MaxMmrRange > 0`, значение `Delta` ограничивается этим порогом).*
4. **Фильтрация кандидатов:** Движок ищет следующих по списку игроков, у которых $\vert{}\text{MMR}_{\text{cur}} - \text{MMR}_{\text{candidate}}\vert{} \le \text{Delta}$.
5. **Формирование лобби:** Как только набирается нужный кап игроков (`Solo` = 2, `Trio` = 6, `Full` = 10), создается объект `MatchResult`, а ID игроков заносятся в `HashSet<long> used`, чтобы исключить дублирование.
6. **Очистка пула:** `MatchmakingLoop` получает список готовых `MatchResult` и удаляет их участников из `MatchmakingManager`.

## 4. Консольный CLI 

Для локальной отладки в `Program.cs` реализован консольный интерфейс ввода команд:

- `add <id> <mmr> <mode>` — добавить одного игрока с указанным MMR в конкретный режим (`solo`, `trio`, `full`).
- `bot <count> <mode>` — закинуть группу ботов со случайным MMR (в диапазоне 800–1500) для нагрузки пула.
- `stat` — вывести текущее количество ждущих игроков во всех трех пулах.
- `exit` — корректно завершить работы фонового потока `MatchmakingLoop` и выйти из программы.

## 5. Пример запуска 

```csharp
using Moba.Matchmaker.Core;
using Moba.Matchmaker.Entities;
using Moba.Shared.MatchmakerLibs;

// 1. Создание менеджера пулов
var manager = new MatchmakingManager();

// 2. Инициализация движока (Базовый разброс 100 MMR, прирост 10 MMR/сек)
var engine = new MatchmakingEngine(baseRange: 100, mmrExpansion: 10);

// 3. Запускфонового цикла опроса
var loop = new MatchmakingLoop(manager, engine);
loop.Start();

// 4. Добавление игроков в очередь
manager.AddPlayer(MatchProperty.Solo, new PoolPlayer 
{ 
    PlayerId = 101, 
    MMR = 1250, 
    JoinedQueue = DateTime.UtcNow 
});
